# 既有检查与新评测分开报告

## 此前检查（背景，不是本仓库结果）

原插件默认开发依赖是 Harness 0.1.5-rc.3。此前运行原项目 61 项测试：59 通过，2 项沿用旧去重预期，和固定提交中的“先过滤已有可见 skill”行为不一致。另有临时诊断测试通过。此处只保留背景，不能当作新评测的通过率或新版本兼容结论。

## 本仓库结果

新项目将同一固定提交的原始源码在 0.1.7-rc.1 的依赖下编译和挂载。实际编译/运行证据由 `reports/compatibility.json` 给出；完整回归由当前 `npm test` 产生。SDK smoke 是真实 Agent 循环，模型响应固定，没有付费 API。

Cordis 原定 4.0.2 与所选 SDK 的 `~4.0.4` peer 冲突，本仓库固定 4.0.4 并保留 npm 锁文件。被测源码和原仓库不作修复。兼容门禁失败会阻断评测并报告。

离线示例的分数与 A/B/C 成败是构造数据，仅验证格式、统计和报告管道。真实准确率和任务收益必须由手动 `eval:selector` / `eval:e2e` 产生。

## 当前宿主限制

在 Codex 的 macOS 执行沙箱中，Harness 的 shell 工具尝试嵌套 `sandbox-exec` 时返回 `SANDBOX_UNAVAILABLE` / `Operation not permitted`。这不是被测插件故障；首版 SDK smoke 验证 skill、资源读取和文件写入。手动完整任务遇到该错误且不能完成验收时，记基础设施失败，不计入条件任务成功率。执行环境不同需要重新验证 shell 后端。

`npm ci` 完成时 npm 上游审计提示存在中等级别漏洞，数量会随 advisory 数据更新；没有在本项目强制升级固定 RC 依赖。详见新验收记录中的安装输出摘要。
